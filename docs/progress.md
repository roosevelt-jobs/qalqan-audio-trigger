# Qalqan Audio Trigger — что сделано и с чем столкнулись

Состояние на 28.10.2026, последний коммит `6a08828`. Подробности по запуску — в `README.md`,
правила и контракты — в `CLAUDE.md`, источники данных — в `docs/data_card.md`.

## Коротко
- **Работает уже сейчас (демо):** сервер с микрофоном и экраном оператора. Детектор C ловит
  кодовые фразы «на помощь» / «көмектесіңдер», детектор B — крик. Тревога приходит в браузер
  с клипом ±5 с, SHA-256 и кнопками «Подтвердить / Отклонить».
- **В работе:** детектор A (своя маленькая модель на кодовые фразы). Код готов, обучение
  перенесено в Google Colab.
- **Тесты:** 125 проходят, `ruff` без замечаний.

## Что делали на каждом этапе

**S0. Каркас проекта.** `uv`, Python 3.11, `pytest`, `ruff`, логирование, `configs/`.

**S1. Источник звука.** Единый интерфейс для микрофона и проигрывания WAV: блоки по 30 мс,
16 кГц, моно. Файлы не в 16 кГц отклоняются с готовой командой конвертации.

**S2. Кольцевой буфер.** Хранит последние 30 с, вырезает клип вокруг события.

**S3. Пробуждение.** Порог громкости + Silero VAD: детекторы работают только когда есть звук.
Громкий звук (крик) будит без VAD.

**S4. Интерфейс детектора.** Общий контракт `Detector`, заглушка по громкости, конвейер
«источник → буфер → пробуждение → детектор».

**S5. Постобработка.** Сглаживание, порог, «N окон подряд», дебаунс: одна тревога на ситуацию.

**S6. События.** JSON + аудиоклип + SHA-256. Событие приходит в два этапа: сразу (без клипа),
потом через 5 с с клипом — чтобы тревога не ждала.

**S7. Сервер и экран оператора.** FastAPI + WebSocket, страница в браузере. Решения оператора
пишутся в журнал (отклонения пригодятся для дообучения). Телеметрия FastAPI выключена.

**S8. Стенд оценки.** FRR (пропуски), FA/h (ложные тревоги в час), DET-кривая, выбор порога —
для любого детектора.

**S9. Детектор B — крик (PANNs Cnn14_16k).** Готовая модель на 527 классов звуков; берём
«крик / возглас». Проверено на FSD50K (287 криков, 3000 негативов): визг ловится в ~60%
случаев, выкрикнутые слова — в 15–25%, ложных тревог ~1,4 в час.
**S9.1** — подбор пробуждения и постобработки: почти ничего не дал.

**S10. Детектор C — кодовые слова через распознавание речи (Vosk, RU + KK).**
Ловит спокойно сказанные фразы, обычную речь пропускает. Ищем слово в распознанном тексте.

**S11a. FSD50K.** Скачан, проверен по md5 и содержимому, переведён в 16 кГц, описан в data card.

**S14a. B и C вместе.** Оба работают параллельно, тревога от любого; срабатывания ближе 3 с —
одна тревога «C+B». У B своё пробуждение (только громкость, без VAD) — так он видит тихий визг.

**S11b. Данные для A.** Готовых записей наших фраз в корпусах почти нет, поэтому: синтез
фраз голосами Piper (6 казахских и 3 русских человека) с проверкой каждой фразы через Vosk,
«ловушки» («скорая помощь», «көмек керек пе?»), обычная речь, живые негативы (Kazakh Speech
Commands, FSD50K), аугментация (шум, эхо, «крик», полоса микрофона). Для проверки отложены
люди целиком.

**S12. Модель A.** Единый модуль признаков (log-mel), DS-CNN на ~88 КБ (цель < 1 МБ), обучение
со сбалансированными классами, детектор `kws` для демо.

**Google Colab.** Загрузчик всех моделей и данных из первоисточников с проверкой хешей,
скрипт установки, ноутбук, архив кода (2,5 МБ) для Google Диска.

## Сложности

### Данные
- **Готовых записей кодовых фраз почти нет.** В открытых корпусах «на помощь» и
  «көмектесіңдер» практически не встречаются (корпуса — это чтение текстов). Модель A учится на
  синтезе — это слабее живых голосов.
- **Мало голосов для синтеза:** 3 русских и 6 казахских человек. Модель может привыкнуть к
  ним и хуже работать на других людях.
- **Нет живых записей для теста.** По правилам проекта синтез нельзя использовать для оценки.
  Без записей фраз (спокойно и в крик, от ~20–30 человек) нельзя честно посчитать пропуски
  у A и C и сравнить A/B/C.
- **Ложные тревоги не подтвердить.** Для цели ≤ 0,1 в час нужно 10+ часов «обычного» звука без
  тревог; сейчас есть ~4–9 часов разнородных клипов.
- **Казахские фразы** (кодовая и «ловушки») подобраны без носителя языка — нужна проверка.

### Качество детекторов
- **Крик со словами не ловит никто.** Распознавание речи (C) не понимает выкрикнутое слово
  («help!» слышит как «me» / «oh»), детектор крика (B) считает его речью. Это главный пробел;
  его должна закрыть модель A, обученная в том числе на «крике» (аугментация).
- **B слабый на выкрикнутых словах** (15–25%), лучше на визге (~60%); ложных тревог 1,4–2,2 в
  час — выше цели 0,1.
- **C реагирует на смысл слова, а не на ситуацию:** «I'm trying to help you» = тревога. Поэтому
  выбрали «на помощь», а не «помогите» («помогите мне поднять»), и «помощь» — как ловушку
  («скорая помощь»).
- **Нагрузка на процессор выше цели 10% ядра:** B ~8%, C ~16% (пока есть звук). Решение — INT8
  (S13) или NPU бейджа.

### Окружение и ресурсы
- **Медленный интернет и лимит 0,5 ГБ на загрузки** на Маке: пропущено аудио MSWC (2,3 ГБ);
  тяжёлые вычисления перенесены в Colab.
- **Мак без вентилятора и с малой памятью:** синтез ушёл в подкачку и шёл медленно.
- **Различия macOS и Linux:** в Colab синтез упал — имя файла из длинной казахской фразы
  превысило лимит Linux 255 байт (на Mac его нет). Исправлено; проверка в Colab ещё впереди.
- **Бесплатный Colab — 2 ядра CPU:** синтез там не быстрее Мака; выигрыш — GPU для обучения.

### Лицензии
- Часть ресурсов только для исследований: голос `ruslan` (CC BY-NC-SA), клипы FSD50K с
  CC BY-NC (1425 из 10 231). Для коммерческого бейджа их нужно будет заменить.
- Программа синтеза Piper — GPL: используется только как отдельный инструмент для генерации
  данных, в продукт не входит.
