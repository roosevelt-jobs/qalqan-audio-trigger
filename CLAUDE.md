# CLAUDE.md — Qalqan Audio Trigger (MVP)

Этот файл — главный контекст и свод правил для Claude Code в этом репозитории.
Читай его целиком в начале каждой сессии. Если что-то в задаче противоречит этому файлу, остановись и спроси.

---

## 1. Что мы строим

**Qalqan Badge** — камера-бейдж для полицейских и медиков (Казахстан). Этот репозиторий — **MVP звукового триггера тревоги**, без самого бейджа: вход — микрофон ноутбука (MacBook Air M2).

Цель MVP: работающий прототип, который слушает микрофон, «просыпается» на речь/звук, детектирует тревожный звуковой сигнал и показывает тревогу оператору в браузере с кнопками «Подтвердить / Отклонить».

**Тип триггера ещё не выбран.** Поэтому детектор — сменный модуль, и MVP сравнивает несколько детекторов на одном стенде:

| ID | Детектор | Что ловит | Обучение |
|---|---|---|---|
| A | KWS (keyword spotting) | Заранее заданная кодовая фраза (RU и KZ) | Нужно обучать |
| B | SED (sound event detection) на предобученной PANNs | Крик, возглас и др. классы AudioSet | Не нужно (позже — дообучение головы) |
| C | ASR + поиск слов (Vosk / faster-whisper) | Слова в распознанной речи | Не нужно (базовая линия) |

Итог MVP — не «одна модель», а **таблица сравнения A/B/C** по метрикам раздела 6 и живое демо.

Принципы проекта, которые нельзя нарушать:
- Всё работает **офлайн и локально**. Никаких облачных ML API (OpenAI, Google, Azure и т. п.).
- Только открытые библиотеки и модели. Проприетарные SDK (например, Picovoice Porcupine) не используем.
- ML не принимает решений сам: тревогу подтверждает человек (оператор).
- Языки фраз: **русский и казахский**.

## 2. Архитектура

### 2.1 Конвейер реального времени

```
Микрофон (16 кГц, моно, float32)        ← или WAV-файл в режиме replay
   │
   ▼
Кольцевой буфер (последние 10–30 с)
   │
   ▼
Пробуждение: порог громкости → VAD (Silero VAD)     — всегда включено, дёшево
   │ активность есть
   ▼
Детектор (сменный: A / B / C, один или несколько параллельно)
   │ поток оценок (score) по окнам
   ▼
Постобработка: сглаживание → порог → N срабатываний подряд → дебаунс
   │ событие
   ▼
Событие тревоги: JSON + аудиоклип из буфера (−5 с … +5 с) + SHA-256 клипа
   │
   ▼
Мини-сервер: FastAPI + WebSocket
   │
   ▼
Веб-экран оператора: тревога, уверенность, прослушать клип, «Подтвердить / Отклонить»
   └─ решение оператора логируется; отклонения = hard negatives для дообучения
```

### 2.2 Офлайн-контур (данные и обучение)

```
Готовые корпуса (MSWC, KSC/KSC2, ISSAI multilingual, Common Voice, FSD50K)
Свои записи (только для теста)            TTS-синтетика (только для обучения)
            └───────────────┬───────────────┘
                            ▼
Подготовка данных: нарезка слов (forced alignment), разбиение по дикторам, аугментации
                            ▼
Обучение (PyTorch, Mac M2 через MPS или сервер)
                            ▼
Оценка: FRR по условиям, FA/h на длинном негативном потоке, DET-кривая
                            ▼
Экспорт: ONNX + INT8 (ONNX Runtime)
                            ▼
Детектор подключается в конвейер (блок A/B/C)
```

### 2.3 Соответствие будущему бейджу (для понимания, не для реализации сейчас)
Пробуждение → MCU на Zephyr; детектор → NPU Rockchip RV1126B; мини-сервер → бэкенд в ЦОД РК; экран → рабочее место диспетчера.

## 3. Контракты между модулями

Эти интерфейсы — договор. Менять их можно только с явного разрешения пользователя.

- **Аудио:** `numpy.ndarray`, `dtype=float32`, моно, `sample_rate = 16000`, значения в [-1, 1]. Блоки по 10–30 мс (по умолчанию 480 сэмплов = 30 мс).
- **Источник звука:** общий интерфейс для микрофона и replay WAV — итератор блоков одинакового формата.
- **Детектор** (`src/qat/detectors/base.py`):
  ```python
  class Detector(Protocol):
      name: str            # "kws", "sed_panns", "asr_keywords"
      version: str
      window_sec: float    # длина окна анализа
      hop_sec: float       # шаг окна
      def process(self, audio_window: np.ndarray) -> float: ...   # оценка 0..1 для одного окна
      def reset(self) -> None: ...
  ```
- **Событие тревоги** (JSON):
  ```json
  {
    "event_id": "uuid4",
    "timestamp_utc": "ISO-8601",
    "detector": "kws",
    "detector_version": "0.1.0",
    "score": 0.93,
    "threshold": 0.8,
    "clip_path": "events/<event_id>.wav",
    "clip_sha256": "hex",
    "clip_start_offset_sec": -5.0,
    "clip_end_offset_sec": 5.0,
    "operator_decision": null
  }
  ```
  Событие выдаётся в два этапа (согласовано в S6 ради задержки ≤ 500 мс): сразу при срабатывании — с `clip_path`, `clip_sha256`, `clip_start_offset_sec`, `clip_end_offset_sec` = `null`; после записи клипа — тот же `event_id` с заполненными полями. Смещения — фактические (клип обрезается у начала/конца потока, тишиной не дополняется).
- **Признаки:** один модуль `src/qat/features.py` для обучения И для runtime (log-mel, 40 полос, окно 25 мс, шаг 10 мс). Дублировать код признаков запрещено.

## 4. Порядок разработки: сервисы строим ПО ОДНОМУ

Это главное правило работы в репозитории.

### 4.1 Правила
1. **Одна задача = один сервис из таблицы 4.2.** Не начинай следующий, пока текущий не закрыт и пользователь не подтвердил.
2. **Перед кодом — короткий план:** какие файлы создаёшь, какой интерфейс, какие зависимости добавляешь, как проверишь. Дождись «ок» от пользователя.
3. **Не трогай файлы других сервисов.** Если для текущего сервиса нужно изменить уже готовый — остановись и спроси.
4. **Сервис закрыт, только когда:**
   - код написан и `pytest` для него проходит (ты реально запустил тесты и видел вывод);
   - `ruff check` чистый;
   - в README добавлен раздел «как запустить/проверить» для этого сервиса;
   - в таблице 4.2 обновлён статус.
5. **Зависимости добавляй по одной** в `pyproject.toml`, с причиной в описании коммита. Никаких «на будущее».
6. Маленькие коммиты, сообщение вида `S3: ring buffer + tests`.

### 4.2 Список сервисов и статус

| # | Сервис | Модули | Готово когда | Статус |
|---|---|---|---|---|

| S1 | Источник звука | `runtime/audio_io.py`: микрофон (`sounddevice`) + replay WAV | Тест: replay WAV отдаёт блоки нужного формата; ручная проверка микрофона на Mac | ☑ |

| S10 | Детектор C (ASR) | `detectors/asr_keywords.py` | Подключён в конвейер, прогнан через стенд S8 | ◐ детектор + юнит-тесты (Vosk RU/KK); список слов, реестр и стенд — позже |
| S11 | Данные для A | `data/`: загрузчики корпусов, нарезка слов, разбиение по дикторам, аугментации | Data card, воспроизводимые сплиты | ◐ S11a готово: FSD50K eval для теста B (`data/fsd50k.py`, data card); S11b (корпуса для A) — после выбора кодовых слов |

| S13 | Экспорт | `export.py`: ONNX + INT8 | Метрики после квантования почти не упали; замер CPU и задержки | ☐ |

## 5. Правила против галлюцинаций

1. **Не выдумывай API библиотек.** Если не уверен в сигнатуре — проверь в установленной версии (`python -c "import x; help(x.y)"`, исходники в `.venv`) или в официальной документации. Не пиши код «по памяти» для библиотек, которые не проверил.
2. **Не выдумывай названия моделей, датасетов, URL, путей и чекпоинтов.** Если нужен файл, которого нет в репозитории, — скажи, что нужно скачать, и попроси пользователя. Большие файлы (веса, датасеты) сам не скачивай без разрешения.
3. **Не утверждай, что что-то работает, пока не запустил.** «Тесты проходят» = ты запустил `pytest` и видел вывод. Если запустить не можешь (например, нужен микрофон) — так и напиши и дай пользователю команду для ручной проверки.
4. **Никаких фиктивных реализаций, выдаваемых за настоящие.** Заглушка допустима только если она явно названа заглушкой (как `detectors/energy.py`) и это записано в таблице 4.2.
5. **Не подгоняй тесты под код.** Если тест падает — чини код или спроси, а не ослабляй тест.
6. **Явно помечай допущения** комментарием `# ASSUMPTION:` и неизвестное — `# TODO(verify):`. Перечисли их в конце ответа.
7. **Если задача неоднозначна — спроси, а не угадывай.** Один уточняющий вопрос дешевле переделки.
8. **Не расширяй объём работы.** Не добавляй фичи, оптимизации и рефакторинги, о которых не просили.
9. Пункты, помеченные в этом файле `[CHECK]`, — непроверенные. Перед использованием проверь и сообщи результат.

## 6. Метрики (цели MVP, ориентиры)

| Метрика | Цель | Комментарий |
|---|---|---|
| FRR (пропуск), тихо | ≤ 5% | |
| FRR, шум / крик / шёпот / 2–3 м | ≤ 10–15% | считать по условиям отдельно |
| FA/h (ложные тревоги в час) | ≤ 0,1 | **главная метрика**; меряется на длинном негативном потоке 30–50+ ч |
| Задержка: конец сигнала → тревога на экране | ≤ 500 мс | |
| CPU | < 10% одного ядра M2 | |
| Размер модели A | < 1 МБ | |

Порог выбирается по DET-кривой (FRR против FA/h), не по accuracy.

## 7. Данные

- **Ключевые слова:** MSWC (50 языков, CC-BY 4.0, слова нарезаны forced alignment из Common Voice — разметка шумная); Multilingual Speech Commands (15 языков, вкл. RU/KK, CC BY 4.0, только словарь Google Speech Commands); KSC/KSC2 и ISSAI multilingual (KZ + RU) — для самостоятельной нарезки слов.
- **Звуковые события:** FSD50K (200 классов AudioSet; у клипов свои лицензии) [CHECK лицензии отдельных клипов для коммерческого использования позже].
- **Негативный поток для FA/h:** склейка речи из KSC/OpenSTT/Common Voice + шумы.
- **Свои записи:** только для теста (крик, запыхавшись, расстояние, разные микрофоны). TTS — только для обучения, никогда для теста.
- **Разбиение строго по дикторам.** Один диктор не может быть в train и test одновременно.
- Данные не коммитим в git. Пути задаются в `configs/data.yaml`.
- [CHECK] наличие моделей Vosk для казахского; лицензии Silero VAD / PANNs / TTS-моделей.
  Проверено: Vosk для казахского есть (`vosk-model-small-kz-0.42`, Apache 2.0); Silero VAD — MIT;
  PANNs — код MIT, веса CC BY 4.0. TTS-модели — не проверено.

### 7.1 Откуда брать датасеты

- **Hugging Face — основной источник**, но только репозитории самих авторов (например, ISSAI для KSC2, MLCommons для MSWC). Загрузка через `datasets`, версия фиксируется по коммиту (`revision=`).
- **Common Voice НЕ берём с Hugging Face.** С октября 2025 г. Mozilla раздаёт Common Voice только через Mozilla Data Collective (нужен аккаунт и принятие условий). Скачивает пользователь вручную; ты только читаешь локальные файлы.
- **Kaggle — только если нет оригинала.** Если датасет найден на Kaggle, сначала найди первоисточник и бери оттуда. Перезаливку без указанного первоисточника не используем.
- Если доступ к датасету требует логина, токена или принятия условий — не пытайся обойти, попроси пользователя скачать.

### 7.2 Проверка каждого датасета перед использованием (обязательно)

Прежде чем писать загрузчик, проверь датасет по списку и запиши результат в `docs/data_card.md`. Если пункт не удаётся проверить — пиши «не проверено», не угадывай.

| # | Что проверить | Почему важно | Если не так |
|---|---|---|---|
| 1 | Первоисточник: кто собрал, есть ли статья, ссылка на оригинал | Перезаливки бывают изменены | Найти оригинал или не использовать |
| 2 | Есть ли ID дикторов | Без них нельзя разбить train/test по дикторам | Только для обучения, **никогда для теста** |
| 3 | Аугментирован ли заранее (копии одной записи с шумом, сдвигом и т. п.) | Копии в train и test = утечка, завышенные метрики | Только для обучения, **никогда для теста** |
| 4 | Как получена разметка: вручную или автоматически (forced alignment) | Автоматическая разметка шумная (обрезанные/не те слова) | Пометить как шумный; выборочно прослушать 50 клипов |
| 5 | Формат: частота, каналы, кодек | Всё приводится к 16 кГц, моно, WAV float32 | Конвертировать в `data/processed/`, оригинал не трогать |
| 6 | Лицензия | Воспроизводимость и будущее коммерческое использование | Записать как есть |
| 7 | Версия: коммит HF / версия релиза / дата скачивания | Чтобы через месяц знать, на чём обучена модель | Зафиксировать в `configs/data.yaml` |
| 8 | Объём, языки, баланс классов, наличие нужных слов/классов | Понять, хватит ли данных | Записать числа |

### 7.3 Data card

`docs/data_card.md` ведётся с первого датасета. Для каждого датасета — блок:

```markdown
## <название>
- Источник (оригинал): <URL>
- Откуда скачан: <HF repo@revision | Mozilla Data Collective | сайт автора>
- Версия / дата скачивания:
- Лицензия:
- Языки:
- Объём: часов / клипов / дикторов
- ID дикторов: есть / нет
- Предварительная аугментация: есть / нет / не проверено
- Разметка: ручная / автоматическая (как)
- Исходный формат → приведён к: 16 кГц моно WAV
- Назначение в проекте: обучение / негативный поток FA/h / тест
- Известные проблемы:
```

Правило назначения: **тест** = только датасеты с ID дикторов, без предварительной аугментации, плюс свои записи. Всё остальное — только обучение и негативный поток.

## 8. Окружение и стек

- MacBook Air M2 (Apple Silicon, без CUDA). PyTorch через `mps`, fallback на `cpu`. Учти, что Air без вентилятора и на долгом обучении сбрасывает частоту.
- Python 3.11, менеджер `uv`.
- Аудио: `sounddevice`, `soundfile`, `torchaudio` или `librosa` (выбрать одно для признаков).
- VAD: Silero VAD. SED: PANNs. ASR: Vosk или faster-whisper.
- Обучение: PyTorch; конфиги YAML; фиксированные seed.
- Экспорт: ONNX, ONNX Runtime (INT8).
- Сервер/UI: FastAPI, WebSocket, одна HTML/JS-страница без сборщиков.
- Качество: `pytest`, `ruff`.

## 10. Чего не делать

- Не подключать облачные API и телеметрию.
- Не сохранять сырое аудио, кроме клипов событий и явно собранных датасетов.
- Не создавать транскрипты всей речи вне детектора C и не сохранять их на диск.
- Не начинать несколько сервисов одновременно.
- Не менять контракты раздела 3 без разрешения.
